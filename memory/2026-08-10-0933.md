# 2026-08-10 — Fix implementer model display mismatch

## Problem

The webchat session header showed the implementer agent running `ollama/ornith:35b` with `?/262k` tokens, but `session_status` confirmed the actual runtime model was `ollama/qwen3.6:27b`.

## Root Cause

`qwen3.6:27b` was missing from the registered Ollama models list in `~/.openclaw/openclaw.json` under `models.providers.ollama.models`. The agent-level config correctly assigned `qwen3.6:27b` to the implementer, so the gateway resolved it at runtime — but the UI display layer had no registry entry to match against and fell back to a different registered model (`ornith:35b`).

## Fix

Added `qwen3.6:27b` to the Ollama models registry in `~/.openclaw/openclaw.json`:

```json
{
  "id": "qwen3.6:27b",
  "name": "qwen3.6:27b",
  "contextWindow": 262144,
  "maxTokens": 8192,
  "input": ["text"],
  "params": { "num_ctx": 262144 },
  "reasoning": true,
  "compat": {
    "supportsTools": true,
    "supportsUsageInStreaming": true
  }
}
```

Then restarted the gateway with `openclaw gateway restart` to reload config.

## Lesson

Whenever an agent model is assigned but not in the registered models list, the UI will show incorrect/fallback model info even though runtime resolution works fine. Always keep the registry in sync with assigned models.
