### Design Decisions

1. **Version source of truth**: `ds_eo_manifest.yaml` package version. The workflow will read this as the canonical version and sync it to `__init__.py`.

2. **Release trigger**: A **manual GitHub Actions workflow_dispatch** event — developers run "Release DS-EO" from the GitHub Actions UI or CLI, never auto-triggered on every push/PR.

3. **Version bump logic**: Semantic versioning (semver). The workflow accepts `major`, `minor`, or `patch` as a parameter; defaults to `patch`. It reads the last tag, bumps accordingly, and generates the next version string.

4. **Release branch**: Releases are created from `main`. No release branches — this keeps it simple and avoids drift.

5. **Duplicate prevention**: Check if the computed tag already exists in the repo (local + remote). Skip if duplicate.

6. **Safety**: Tests must pass before any write operations. All version/tag/release commits happen atomically in one push within the workflow.

7. **Release notes generation**: The workflow generates release notes automatically from git log since the last tag, cross-referenced with CHANGELOG.md for descriptive summaries.

8. **GITHUB_TOKEN**: Uses the built-in `secrets.GITHUB_TOKEN` — no personal access tokens needed.
